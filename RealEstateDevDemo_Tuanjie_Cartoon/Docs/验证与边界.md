# 验证结果与交付边界

更新日期：2026-11-03。对应团结 1.10.4 立体轴向修复版。

## 真实团结反馈与本次修复对象

上一精细立体版并非只做静态检查：用户已在真实团结引擎 1.10.4 中打开并 Play，提供的实际运行截图暴露了以下故障：

- 整片地表错误变红；
- 树木等元素出现异常荧光绿色；
- 左侧行动按钮和顶部多个控制按钮只有背景，标题完全消失；
- 部分文字在非整数 Game 视图缩放下仍显模糊。

这次反馈推翻了“静态验证通过即可交付”的判断。本版优先修复实际渲染与文本故障，不用 Blender 预览或 Core 测试代替实机画面验收。

已定位并修改：

1. **按钮无字的确定原因**：`Button` 把占位名 `"Text"` 传给 `Label`，而 `Label` 只调用 `RequestCharactersInTexture`，从未给 `Text.text` 赋值。现在 `Label` 写入实际显示内容，`Button` 直接传真实标题。
2. **字形预加载覆盖不全**：原来只给少数字段统一请求 30 / 24 号字。现在遍历全部 UI Text，按各自实际内容、字号和字体样式请求。
3. **渲染路径存在兼容风险**：删除自定义 `LightingToonRamp`、`LightingTerrainRamp` 和色向外推；地形改为显式 `COLOR` 语义 + 标准 Lambert，模型也使用标准 Lambert。
4. **同名 Shader 重复**：删除旧的 `Assets/Shaders/GridTerrain.shader`，只保留 `Assets/Resources/Shaders/GridTerrain.shader`。
5. **材质切换可能丢属性**：模型切换 Shader 前读取原颜色与贴图，切换后显式写回；不支持自定义 Shader 时保留导入器的 Built-in 材质。

## 第二次真实团结反馈：楼体为什么变成“纸板”

用户运行上一修复版后提供的新截图表明：按钮标题已经出现，地表不再纯红，但建筑基座竖起、楼体向画面深处躺倒，树木和路灯也有倾倒迹象。这仍不是可接受的模型效果。

本次直接解析了 `SM_HQ.fbx` 的二进制节点属性：

- FBX 全局设置为 Y Up；
- 根节点 `SM_HQ` 带有 `Lcl Rotation = (-90, 0, 0)`；
- `Main building volume` 和 `Beveled site foundation` 仍保留各自正确的 Blender 局部位置；
- 因而源模型并非只有一块板，问题是 Unity 运行时覆盖根旋转。

旧 `ModelLibrary.Spawn` 直接返回 FBX 根实例，场景随后设置 Y 轴朝向，清除了根节点的 X = −90°。当前改为 `_Controller` 外层 + FBX 内层：外层负责游戏变换，内层通过 `SetParent(controller, false)` 保留导入旋转和缩放。所有静态朝向与挖机逐帧动画均通过外层生效。

同时根据这张实机截图，降低方向光、环境光与地形过亮色值，减少道路标线密度，并把默认镜头转到能同时看见正立面和侧面的方向。
