# 房地产开发模拟器 Demo：Blender → 团结引擎 / Unity 2022 全流程手把手教程

> 最后更新：2026-11-03｜本分支推荐环境：Windows 10/11、团结引擎 1.10.4（API 基线 Unity 2022.3 LTS）、Blender 5.x、.NET 8 SDK
> 难度：入门到中级｜首次运行约 15 分钟｜完整学习与改造约 2—4 小时

## 教程概览

本教程面向“会用电脑，但不一定做过 Unity 游戏”的读者。完成后，你可以在本机打开完整 Unity 工程，试玩“随机地图 → 公开竞价 → 勘测设计 → 施工组织 → 动态建造 → 70% 预售 → 回款结算”的 Demo；也可以修改经营数值、重新生成 Blender 模型、运行核心测试并打包 Windows 程序。

**先分清两件事：**

- **只想试玩**：只需 Unity，直接看步骤 1—3。FBX、字体和配置已经随工程提供，不必先安装 Blender。
- **想做全流程开发**：再安装 Blender 与 .NET 8 SDK，执行步骤 4—8。

本工程使用 Unity 内置渲染管线、旧版 Input Manager 和 uGUI。地图、镜头、灯光、UI 都由 C# 自动创建，不要求你在编辑器里手工拖拽几十个组件。

## 1. 前置知识

### 必须掌握

- **Windows 基本文件操作**：需要解压工程、找到目录、打开终端；否则无法区分工程根目录与 Unity 子目录。
- **Unity 编辑器基本界面**：需要认识 Project、Hierarchy、Scene、Game、Console 和 Play 按钮（推荐资源：Unity Manual 的 Editor Interface 章节）。
- **C# 基础阅读**：改数值和增加按钮时需要理解类、方法、字段、`if` 与集合（推荐资源：Microsoft Learn 的 C# 入门）。

### 了解即可

- **Blender 对象层级**：重新建模时会接触根节点、子对象、材质和 FBX 导出；脚本已经封装好基础操作。
- **JSON**：数值配置与存档都使用 JSON；教程只要求会修改数字并保持逗号正确。
- **命令行**：核心测试与 Blender 批处理会用到；每条命令均可直接复制。

不需要先学着色器、网络编程、ECS、URP 或 IL2CPP，它们不是本 Demo 的前置条件。

## 2. 环境搭建

### 2.1 工具清单

| 工具 | 推荐版本 | 是否必须 | 用途 |
|---|---|---:|---|
| 团结 Cowork / 团结 Hub | 当前稳定版 | 必须 | 安装并选择团结引擎；也可用 Unity Hub 回退验证 |
| 团结引擎或 Unity Editor | 团结引擎 1.10.4；回退用 Unity 2022.3 LTS 任一补丁版 | 必须 | 打开、运行和打包工程 |
| Windows Build Support | 与编辑器同版本 | 打包时需要 | 生成 Windows x64 程序 |
| Blender | 5.x，本次资产实测为 5.2.1 LTS | 重建模型时需要 | 编辑 `.blend`、运行 `bpy` 脚本 |
| .NET SDK | 8.x | 运行测试时需要 | 独立编译并测试纯 C# 内核 |
| Node.js | 支持当前 `three` 的版本 | 仅重新转换 GLB 时需要 | 运行 AssetBridge；普通重建不需要 |

### 2.2 安装团结引擎 / Unity 2022

1. 安装团结 Cowork / 团结 Hub，并安装团结引擎当前稳定版。
2. 若团结引擎导入异常，可用 Unity Hub 安装任一 Unity 2022.3 LTS 补丁版先验证工程，再迁移回团结引擎。
3. 若准备打包 Windows，在安装模块中勾选 Windows Build Support。
4. 不需要额外安装 URP、HDRP、Input System 或 TextMeshPro；`Packages/manifest.json` 已声明 uGUI 与所需基础模块。
5. 安装后确认能新建并打开一个空项目，再关闭测试项目。

**验证**：Unity Hub 的 Installs 页面能看到对应版本，且编辑器可以正常启动。

### 2.3 安装可选开发工具

**Blender**：使用 Blender 官方安装包。若要从终端调用，可将安装目录加入 PATH；也可以全程使用 Blender 的“文本编辑器 → 打开 → 运行脚本”。

```bash
blender --version
```

若系统找不到命令，不代表 Blender 没装好，只是没有加入 PATH；步骤 6 给出界面操作与完整路径两种办法。

**.NET 8 SDK**：仅核心自动化测试需要。

```bash
dotnet --version
```

预期输出以 `8.` 开头。只打开 Unity 工程时无需安装它。

## 3. 核心步骤

以下命令默认都在工程根目录执行，也就是包含 `Assets`、`Packages`、`ProjectSettings` 和 `Tools` 的目录。

### 步骤 1：打开工程并完成首次资源检查

**目标**：让团结引擎识别场景、20 个精细立体卡通 FBX、中文双字体、城市图标、两个 Shader、配置和全部 C# 脚本。

**操作**：

1. 完整解压工程，不要只解压 `Assets`，否则引擎缺少工程设置。
2. 团结 Hub / 团结引擎 1.10 → **打开或添加项目**，选择 `RealEstateDevDemo_Tuanjie_Cartoon` 工程根目录。
3. 首次打开会导入 FBX 和字体，等待导入与脚本编译结束。
4. 双击 `Assets/Scenes/Main.unity`。这个场景故意保持为空，运行时由 `DemoBootstrap` 自动组装。
5. 点击菜单 **房地产 Demo → 检查 Demo 资源**。
6. 打开 Console，确认出现“资源检查通过”。

**解释**：

- `Main.unity` 为空不是漏文件；自动入口是 `RuntimeInitializeOnLoadMethod`。
- FBX 位于 `Assets/Resources/Models`，因此能用 `Resources.Load<GameObject>("Models/模型名")` 加载。
- `DemoEditorTools` 会自动设置本目录模型的缩放、动画和网格导入参数。

**验证**：菜单检查不抛异常；`Assets/Resources/Models` 中能看到 `SM_Building_Stage0` 至 `Stage4` 等 20 个模型。

### 步骤 2：运行第一个完整经营循环

**目标**：从空场景进入“平坦地面 + 全 3D 建筑与设施”的可操作地图，并完成一个项目。

**操作**：

1. 点击编辑器顶部 **Play**，切换到 **Game** 视图；首次先将 Game 视图固定为 1920×1080、100% 显示比例检查高清卡通 UI，再复测其他分辨率。
2. 点击左侧 **开始公开招标 · A 地块**，也可直接点击地图上的 A 地块。
3. 使用“试探加价 / 标准加价 / 跳价施压”反复报价；信息、资金和纪律类卡牌每场各用一次。
4. 中标后点击 **钻孔勘测**，按需调整户型、层数、朝向、园林、物业、车库，再 **确认设计并组织施工**。
5. 选择施工队，可讲价一次；比较两家建材商的到场价，然后采购材料。
6. 现金不足时先点击 **开发贷 +¥300,000**，必要时使用两次；再点击 **正式开工**。
7. 施工自动推进。进度达到 70% 后选择分批或一次性开盘，并选择售价策略。
8. 用 1× / 4× / 12× 控制速度；交付且全部售罄后查看评级。

**解释**：

- 报价卡可重复，避免还有 AI 在场时无牌可出；其他卡牌每场一次。
- 材料价不是随手填的总价，而是数量、出厂价、道路距离运价、装卸费和地质附加共同计算。
- 进度不足 70% 时销售系统会拒绝开盘，这一规则在内核层校验，不只是隐藏按钮。
- 贷款会增加现金和负债，每月结算利息；不是免费补给。

**验证**：底部日志依次出现中标、采购、进场、阶段切换、销售回款和最终结算；右侧可看到土地成本、工程支出、回款与评级。

### 步骤 3：掌握镜头、保存和读取

**目标**：能检查地图细节，并确认单槽存档可用。

**操作**：

| 操作 | 按键或按钮 |
|---|---|
| 平移镜头 | W / A / S / D |
| 旋转镜头 | Q / E |
| 缩放 | 鼠标滚轮 |
| 拖动平移 | 鼠标中键 |
| 聚焦已竞得地块 | 施工后点击对应地块 |
| 暂停 / 继续 | 顶部“暂停/继续” |
| 时间倍率 | 1× / 4× / 12× |
| 保存 / 读取 | 顶部或左侧对应按钮 |
| 显示格网 | 顶部“格网” |

保存后可在 Console 或提示中看到 Unity 的 `Application.persistentDataPath`，文件名为 `demo_slot_0.json`。

**解释**：存档包含项目、投标、随机数状态和已触发事件；读取后重新生成同一种子地图，再恢复经营状态。保存采用临时文件写入后替换，避免直接覆盖到一半留下半个 JSON。

**验证**：保存 → 继续推进几天 → 读取，日期、现金、施工进度和已售套数应回到保存时点。

### 步骤 4：不改代码，先调整经营数值

**目标**：通过配置改变初始资金、材料价格、贷款利率等参数。

**操作**：

1. 用文本编辑器打开 `Assets/Resources/Config/game_config.json`。
2. 例如把 `"InitialCash": 1500000` 改成 `2000000`，把 `"MonthlyLoanRate": 0.006` 改成 `0.004`。
3. 保持 JSON 格式：最后一项后不要多逗号，字符串使用英文双引号。
4. 回到 Unity，停止后重新 Play，或重新开始一局，使新配置生效。

**解释**：`SaveSystem.LoadConfig()` 启动时读取该文件；`GameConfig.Default()` 是资源缺失时的后备值。若你要永久修改后备默认值，还需同步修改 `Assets/Scripts/Core/GameConfig.cs`。

**验证**：新一局顶部现金变为 ¥2,000,000；后续贷款日志中的月利率变为 0.4%。

### 步骤 5：理解“UI 只找门面”的代码结构

**目标**：知道新增玩法应改哪里，避免 UI、规则、存档互相缠绕。

**操作**：按以下顺序阅读代码：

1. `Assets/Scripts/Unity/DemoBootstrap.cs`：启动、场景创建、时间推进。
2. `Assets/Scripts/Unity/GameHUD.cs`：按钮与信息显示。
3. `Assets/Scripts/Core/GameCore.cs`：对外统一操作入口。
4. `Assets/Scripts/Core/GameState.cs`：所有需要保存的状态。
5. `TenderSystem`、`ConstructionSystem`、`SalesSystem`：具体规则。
6. `Assets/Scripts/Unity/MapView.cs` 与 `ConstructionVisual.cs`：只负责把状态呈现出来。

**解释**：UI 不直接计算材料价、不自行扣土地款，也不决定能否预售；它调用 `GameCore` 或对应公开系统。这样同一套内核可以被 `.NET 8` 测试程序直接运行。

**验证**：在 `GameHUD` 中找到一个操作按钮，能沿调用链定位到 `GameCore`，再定位到具体核心系统。

### 步骤 6：从 Blender 重新生成模型并导入 Unity

**目标**：跑通“卡通参数化建模 → 根节点组织 → FBX → Unity Resources”的资产流水线。

**界面方式**：

1. 启动 Blender，打开脚本 `Tools/Blender/build_cartoon_assets.py`。
2. 在文本编辑器点击 **Run Script**。脚本会清空当前场景，因此不要直接在你的其他 Blender 工程里运行。
3. 等待导出结束，再打开 `Tools/Blender/Output/CartoonRealEstateAssets.blend` 查看可编辑源场景。
4. 回到 Unity 等待 FBX 自动重导入，执行“检查 Demo 资源”。

**命令行方式**（Blender 已加入 PATH）：

```bash
blender --background --python Tools/Blender/build_cartoon_assets.py
```

脚本一次完成精细建模、FBX 导出、`.blend` 保存、卡通总览与模型近景渲染，不必再运行旧版验收脚本。

Windows 未加入 PATH 时，可把 `blender` 换成实际程序完整路径，例如：

```powershell
& "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --python Tools/Blender/build_cartoon_assets.py
```

**解释**：脚本完全通过 `bpy` 创建五个施工阶段、塔吊、挖机、泵车、运输车、供应商、施工队办公室、学校、医院、总部、树木、岩石、路灯、花坛、长椅和别墅，共 20 个模型，不依赖旧版 GLB。建筑、机械、设施和植物均有真实立体几何，地面才保持平坦。每个 `SM_*` 根节点及其子层级单独导出；不要在 Unity 中再盲目做 90° 轴补偿。

**验证**：`Assets/Resources/Models` 的 20 个 FBX 修改时间更新；`Tools/Blender/Output/CartoonRealEstateAssets.blend` 能重新打开；`Docs/Images/卡通资产总览.png` 与 `精细模型近景.png` 重新生成，主体完整且能看清窗框、阳台、屋顶和机械细节。

### 步骤 7：运行不依赖 Unity 的核心测试

**目标**：在修改经营规则后，用自动测试快速发现地图、竞价、施工、销售与存档回归。

**操作**：

```bash
dotnet run --project Tests/CoreSmokeTests.csproj -c Release
```

**解释**：测试工程直接链接 `Assets/Scripts/Core` 下的源码，不需要 Unity 运行时。覆盖地图连通、同种子一致性、三类地质、投标卡牌、现金压力、70% 预售、完整交付销售、JSON 恢复与读档后继续运行。

**验证**：终端最后输出：

```text
ALL GREEN: 64 assertions
```

若失败，先看第一条断言及对应操作，不要靠反复重跑来掩盖确定性错误。

### 步骤 8：打包 Windows x64

**目标**：生成可分发给 Windows 玩家的 Demo 文件夹。

**操作**：

1. 回到 Unity，确认已安装 Windows Build Support。
2. 执行 **房地产 Demo → 一键生成主场景** 可重建空主场景；已有场景时通常不必重复执行。
3. 执行 **房地产 Demo → 检查 Demo 资源**。
4. 执行 **房地产 Demo → 打包 Windows x64**。
5. 成功后查看 `Builds/Windows/RealEstateDemo.exe`，并将整个 `Builds/Windows` 文件夹一起分发，而不是只复制 exe。

**解释**：菜单一键调用 `BuildPipeline.BuildPlayer`，目标为 `StandaloneWindows64`。本仓库交付的是完整 Unity 工程与打包脚本，不附带声称已实机验证的 Windows 可执行包。

**验证**：在目标 Windows 电脑启动程序，完成步骤 2 的最小闭环，并检查存档目录是否可写。

## 4. 常见报错与排查

### 报错 1：菜单检查提示“Unity 尚未导入模型”

完整错误信息示例：

```text
FileNotFoundException: Unity 尚未导入模型：SM_Building_Stage0
```

原因：FBX 文件缺失、尚未完成首次导入，或文件不在 `Assets/Resources/Models`。

解决方案：确认 20 个 FBX 都在该目录；回到 Unity 等待导入，必要时右键 Models → Reimport，再执行资源检查。不要用同名 `.blend` 代替 FBX。

验证修复：Console 出现“资源检查通过”。

### 报错 2：模型变成方块，并出现 Resources 加载警告

原因：`ModelLibrary` 找不到指定模型时会启用占位方块，让经营逻辑仍能运行；这不是模型加载成功。

解决方案：核对警告中的资源名与 FBX 文件名，重点检查大小写、`SM_` 前缀和 `Models` 目录，然后 Reimport。

验证修复：警告消失，地图上显示 Blender 低模而不是纯色方块。

### 报错 3：中文 UI 显示方框

原因：`Assets/Resources/Fonts/NotoSansSC.otf` 或 `NotoSansSC-Bold.otf` 丢失、未导入，运行时只能回退到默认字体。

解决方案：恢复随包双字体，等待引擎导入；检查 `GameHUD.Build` 中路径仍为 `Fonts/NotoSansSC` 与 `Fonts/NotoSansSC-Bold`，再执行资源检查。

验证修复：重新 Play 后中文按钮、日志、粗体标题和成本名称正常显示。

### 报错 4：输入系统异常

完整错误信息示例：

```text
InvalidOperationException: You are trying to read Input using the UnityEngine.Input class, but you have switched active Input handling to Input System package in Player Settings.
```

原因：本 Demo 使用 `Input.GetKey` 等旧版 API，而 Player Settings 被改成仅使用新 Input System。

解决方案：Edit → Project Settings → Player → Active Input Handling，选择 **Input Manager (Old)** 或 **Both**；不要为修这个错误重写整套镜头输入。

验证修复：WASD、Q/E、滚轮与 UI 点击恢复。

### 报错 5：读取时“没有找到单槽存档”

原因：当前 Unity 公司/产品标识对应的 `persistentDataPath` 下还没有 `demo_slot_0.json`，或你更换了工程产品设置。

解决方案：先在当前工程点击“保存”，再读取；若已有旧存档，确认实际提示路径，不要到工程 Assets 目录寻找。

验证修复：保存后该路径出现 JSON，读取成功。

### 报错 6：Blender 运行后卡通模型没有更新

原因：运行了旧教程或其他分支的脚本，脚本没有完整执行，或引擎尚未重新导入 FBX。

解决方案：确认当前工程只使用 `Tools/Blender/build_cartoon_assets.py`；保持完整目录结构并等待日志逐个输出 `EXPORTED SM_*`；回到引擎右键 `Assets/Resources/Models` → Reimport。

验证修复：日志最后输出 `DONE: 20 detailed cartoon assets`，`Docs/Images/卡通资产总览.png`、`精细模型近景.png` 和 20 个 FBX 的修改时间均更新。

### 报错 7：`dotnet` 不是内部或外部命令

原因：未安装 .NET 8 SDK，或安装后终端尚未刷新 PATH。

解决方案：安装 .NET 8 SDK，关闭并重新打开终端，再执行 `dotnet --version`。只玩 Unity 时可跳过测试，不必为此改 Unity 代码。

验证修复：版本输出以 `8.` 开头，测试命令可以启动。

### 报错 8：修改配置后没有生效或 JSON 解析失败

原因：旧场景仍在运行、修改的是后备 C# 而不是 JSON，或 JSON 多逗号、少引号。

解决方案：停止 Play 后重新运行并开新局；用 JSON 校验器检查格式；确认改的是 `Assets/Resources/Config/game_config.json`。

验证修复：新一局初始资金和右侧成本按新配置变化，Console 无解析异常。

### 报错 9：UI 文字模糊、过小或布局拥挤

原因：Game 视图分辨率过低、编辑器缩放比例不合适，或旧版 UI 脚本仍在 Library 缓存中。

解决方案：先把 Game 视图固定为 1920×1080，以 100% 比例检查；确认 `GameHUD` 使用 `NotoSansSC` 与 `NotoSansSC-Bold`、参考分辨率为 1920×1080、`Canvas.pixelPerfect = true`，字体导入为 Dynamic + Smooth；停止 Play 后重新运行。若左右面板空白，检查两个 ScrollRect 根对象是否完整锚定到父容器，不要继续缩小字号。若仍是旧界面，关闭引擎并删除本卡通分支的 `Library` 后重新导入，不要删除其他工程。

验证修复：顶部数据卡完整可见，左右面板显示实际内容且不重叠，主要按钮、日志和结算文字清晰且不截断。

### 报错 10：按钮完全无字、地表纯红或模型异常荧光

原因：这三项不是正常卡通风格，也不能靠调整 Game 视图缩放解决。旧精细版的 `Label` 只请求字形而没有写入 `Text.text`，按钮又传入占位名 `"Text"`；旧自定义 LightingRamp、顶点色写法和重复地形 Shader 则增加了真实团结图形后端的兼容风险。

解决方案：使用当前运行修复版完整工程，不要只把旧场景和新模型混用。检查 `GameHUD.Label` 有 `text.text = value;`，`Button` 传入真实 `label`；确认两个 Shader 均为当前标准 Lambert 版本，并删除 Resources 之外的旧 `GridTerrain` 副本。执行 **房地产 Demo → 检查 Demo 资源**，查看 Shader 是否受当前图形后端支持。

验证修复：重新 Play 后，顶部“保存 / 读取 / 格网”和左侧全部行动按钮都有标题；草地、水面、道路与地块呈现各自色板颜色，树木和建筑不再是异常纯色。当前修复版仍需以此真实团结画面检查为最终验收，静态编译通过不能替代这一步。

### 报错 11：建筑基座竖起、楼体像躺倒的纸板

原因：FBX 根节点带有 X = −90° 的 Blender→Unity 轴向转换。旧代码直接返回 FBX 根实例，随后设置 `localRotation = Quaternion.Euler(0, yaw, 0)`，把 X 旋转覆盖掉。棕色“竖板”其实可能是被竖起的基座底面，不代表 Blender 中没有楼体。

解决方案：使用当前立体轴向修复版的 `ModelLibrary.Spawn`。确认它创建 `_Controller` 外层并返回外层，FBX 模型通过 `model.transform.SetParent(controller.transform, false)` 成为内层子对象。场景只能旋转外层；不要直接把 `Object.Instantiate(prefab)` 的根实例交给朝向代码。默认镜头 `yaw = 220` 用于展示门窗正面和侧面。

验证修复：建筑基座保持水平，楼体竖直，正面门窗、阳台、屋顶和侧面进深同时可见；树木和路灯保持竖直，挖机旋转动画中也不会躺倒。不能只检查 FBX 文件存在或节点数量，必须检查真实 Play 中的世界姿态。

## 5. 进阶拓展

### 方向 1：把 B 地块从展示变成邀请招标｜中级

复制 `GameCore.StartTender` 的入口思路，为地块 1 增加独立邀请条件与 UI；复用 `TenderSystem.Start(lotId)`，不要在 `GameHUD` 里另写一套竞价。测试要新增“两个地块分别中标、退出与成本不串档”。推荐资源：现有 `TenderSystem.cs` 与 `Tests/Program.cs`。

### 方向 2：增加新投标卡牌｜中级

在 `CardType` 添加枚举，在 `TenderSystem.PlayCard` 实现规则，在 `GameHUD.RebuildActions` 添加按钮，最后补核心测试。若状态需要保存，同步修改 `TenderState`，并考虑旧存档版本迁移。推荐资源：Microsoft C# 文档与现有卡牌实现。

### 方向 3：替换施工模型或增加阶段｜中级

优先修改 `Tools/Blender/build_cartoon_assets.py` 的参数化函数，保留 `SM_*` 命名与根节点基座；新增阶段时同步修改 `ConstructionStage`、进度阈值、`ConstructionVisual.Rebuild` 和 Blender 导出清单。推荐资源：Blender Manual 的 Python API、FBX Export 与 Object Parenting。

### 方向 4：强化存档与版本迁移｜高级

当前单槽 JSON 适合 Demo。扩展时可加入 `Version` 升级函数、备份槽、schema 校验与异常恢复；不要只在 UI 隐藏不兼容存档。推荐资源：.NET `System.IO` 文档与现有 `SaveSystem.cs`。

### 方向 5：把静态施工表现升级为真实机械动画｜高级

当前挖机旋转与运输车往返是程序化占位动画，不含骨骼动画。可在 Blender 中制作动画片段，导出后由 Unity Animator 按 `ConstructionStage` 驱动，并用事件保证动画与经营进度一致。推荐资源：Unity Manual 的 Animation 与 Animator Controller。

### 可独立完成的练习项目

- **供应商比价面板**：把道路距离、运价、装卸费拆成两列，练习 `CostEngine` 与 uGUI。
- **投标复盘工具**：记录每次玩家出价和 AI 反应，结算时输出时间线，练习状态与日志设计。
- **新地质剧本**：增加一种地质及其成本、事件和测试，练习跨模块扩展。

### 最佳实践

- 规则判定放 Core，按钮放 Unity；不要用 UI 文案代替现金、进度等底层校验。
- 新状态先进 `GameState`，再写保存/读取与继续运行测试，避免“能玩但不能存档”。
- 不随机修改多个数值来掩盖失败；用固定种子复现，再定位成本、工期或销售概率。
- 模型保留一个根节点和统一尺度，Unity 只通过父级摆放，不对子对象逐个补偿旋转。
- 打包前至少完成一次冷启动、完整闭环、保存读取和目标电脑测试；编辑器能 Play 不等于 exe 已验证。
