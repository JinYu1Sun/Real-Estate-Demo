# 卡通视觉与界面规范

更新日期：2026-11-03。本文件对应当前 `RealEstateDevDemo_Tuanjie_Cartoon` 分支。

## 1. 视觉目标

整体方向是“可操作的玩具城市”：圆润、明亮、清晰、有活力，但不靠牺牲文字可读性换取卡通感。地图、建筑、施工机械和 UI 共用珊瑚橙、青绿、亮黄、天蓝与深海军蓝，避免场景和界面像两套游戏。

本版是原创程序化低模 Demo，不复制任何具体商业游戏的模型、界面或素材。

## 2. UI 层级与字体

入口：`Assets/Scripts/Unity/GameHUD.cs`。

- 画布原生参考分辨率为 `1920×1080`，使用 `CanvasScaler.ScaleWithScreenSize` 与 `Canvas.pixelPerfect`；优先在 100% Game 视图检查，避免非整数缩放造成文字发虚。
- 顶部为 112 像素高的品牌与资金区；品牌图标使用 `Resources/Art/CityLogo.png`，长资金数字启用 BestFit 防止溢出。
- 左侧为行动面板，右侧为项目情报，底部中央仅保留短日志；中央地图不再被整条日志遮挡。
- 顶部下方用阶段条提示“拿地 → 设计 → 施工 → 预售 → 结算”。
- 普通行动按钮高度 60，按钮正文 20，情报正文 20，面板标题 25，关键数字 24；动态字形逐文本按实际内容、字号和字体提前请求，字体导入使用 Dynamic + Smooth，并保留字体数据。
- `Label` 必须把显示值写入 `Text.text`；`Button` 必须把真实按钮标题传给 `Label`，不能用仅用于对象命名的 `"Text"` 占位符。否则会出现按钮背景正常、标题完全为空。
- 正文：`Resources/Fonts/NotoSansSC.otf`；标题、按钮和关键数字：`NotoSansSC-Bold.otf`。
- 面板和按钮使用 128×128 抗锯齿圆角 Sprite；主要面板带轻微向下阴影。左右 ScrollRect 根对象必须完整锚定到父容器，避免 viewport/content 尺寸链路异常导致空白。

新增界面时优先复用 `Panel`、`Label`、`Button`、`ActionButton` 和 `Anchor`，不要在多个方法里各写一套字体与颜色。

## 3. 核心色板

| 用途 | RGB | 说明 |
|---|---|---|
| 深色文字 / Ink | `24, 50, 77` | 奶油底上的正文，避免浅灰小字 |
| 顶栏 / Navy | `23, 48, 75` | 品牌区、地块招牌 |
| 顶栏卡片 / NavySoft | `39, 70, 101` | 与顶栏拉开轻微层级 |
| 面板 / Cream | `255, 248, 232` | 行动与情报区的暖色底 |
| 青绿 / Teal | `18, 181, 165` | 普通行动、阶段标题、玻璃与栏杆 |
| 橙色 / Orange | `255, 157, 35` | 开始、确认、开工、开盘等主行动 |
| 珊瑚 / Coral | `255, 103, 91` | 退出、提示、屋顶与阳台 |
| 天蓝 / Sky | `72, 160, 255` | 设置、设计选项、屋顶 |
| 紫色 / Purple | `143, 99, 214` | 贷款、倍率和工程信息 |

颜色集中在 `GameHUD` 顶部静态字段中。新增状态色应从同一色板的明度与饱和度阶梯推导，不再引入另一套灰蓝商务配色。

## 4. 地图与场景

入口：`MapView.cs`、`CameraRig.cs`、`DemoBootstrap.cs`。

- 地形：表现层地面保持平坦，鲜绿草地、青蓝水面和明亮沙滩位于实心土壤地基上；Core 的地质高度、道路距离和经营计算不变。
- 道路：浅色路肩 + 蓝灰沥青 + 黄色短标线；仍由合并 Mesh 绘制，不逐格创建大量 GameObject。
- 地块：立体角柱、绿色内草坪、深蓝招牌和独立粗体中文 TextMesh；文字由 BillboardLabel 面向镜头，不继承招牌的非均匀缩放。
- 装饰：根据地图种子确定性摆放立体树木、岩石、路灯、花坛、长椅和别墅，避开水面、道路、地块和功能建筑。
- 灯光：方向光强度 `0.82`，软阴影；Flat 环境光强度 `0.65`，环境色为 `(0.38, 0.44, 0.48)`，关闭雾，避免高环境光把糖果色洗白或草地过曝。
- 镜头：正交等距视角，默认 `yaw = 220`，可同时看到建筑门窗正面与侧面；初始 `orthographicSize = 36`，滚轮范围 `18—110`，聚焦地块时为 26。
- 道路标线每四格出现一次，不再每隔一格密集重复；草地、水面和路肩色值均已降低过亮分量。

修改地图颜色时只改 `TerrainColor` 和 `BuildRoads` 的色值；不要改动 Core 中的地图种子、道路连通和运输距离规则。

## 5. 模型与卡通光照

建模入口：`Tools/Blender/build_cartoon_assets.py`。

- 20 个模型全部由 Blender `bpy` 参数化生成，不依赖旧版 GLB；新增路灯、花坛、长椅和别墅。
- 每个资产保留独立 `SM_*` 根节点，按根节点及子层级导出 FBX。
- 成品楼使用六层实体楼体、三面窗框与玻璃、窗棂窗台、挑出阳台、逐根栏杆、花盆、空调外机、入口台阶与门廊、屋顶花园房和分格太阳能板。
- 施工五阶段继续对应 Core 的进度阈值；桩基钢筋、防护栏、核心筒、外部楼梯、塔吊桁架与拉索、挖机履带与挖斗齿、泵车支腿等均为真实几何，美术替换不改变预售规则。
- `ModelLibrary.Spawn` 返回独立的 `_Controller` 外层节点，外层负责游戏世界的平移、缩放和 Y 轴旋转；FBX 实例作为内层子对象，使用 `SetParent(controller, false)` 保留导入器的局部旋转与缩放。禁止再把 FBX 根实例直接返回给场景旋转，否则会覆盖其 X = −90° 轴向转换并使楼体躺倒。
- Unity 通过 `ModelLibrary.ApplyToonShader` 将导入材质切换到 `Resources/Shaders/ToonLit`；切换前读取、切换后写回原材质的 `_Color` 与 `_MainTex`。Shader 不存在或不受当前图形后端支持时，保留导入器的 Built-in 材质作为安全回退。
- `ToonLit` 与 `GridTerrain` 均使用标准 Lambert，不再使用自定义 LightingRamp、色向外推或其他可能改变色相的计算。地形通过 `float4 color : COLOR` 显式传递顶点色；工程内只允许一个 `RealEstate/GridTerrain` 定义。
- 这次调整针对真实团结截图中的红色地表和异常荧光色，目标是让颜色可预测地来自网格顶点色或 FBX 材质，而不是在 Shader 中再次改色。

重建命令：

```bash
blender --background --python Tools/Blender/build_cartoon_assets.py
```

预览输出：`Docs/Images/卡通资产总览.png` 与 `Docs/Images/精细模型近景.png`。预览使用 Standard 色彩变换，避免高亮糖果色过度洗白；它们用于检查模型细节，不是 Unity 实机截图。

## 6. 修改时保持不变的边界

- 不在 UI 内另写经营规则；操作仍调用 `GameCore` 或对应系统。
- 不改变 `GameState.Version` 和已有字段来“修美术”。
- 不把 Unity 6 专属对象查找 API 引回本分支。
- 不删除 Resources 下的字体、图标或 Shader；编辑器资源检查会检查这些资源。
- 不用静态编译或 Blender 预览替代团结 1.10 实机验收。

## 7. 本机视觉验收清单

1. 先在 1920×1080、100% Game 视图检查顶栏、左右面板和字体，再在 1600×900 下复测；确认行动区与情报区不为空白。
2. 检查长按钮文字、材料报价、结算评级是否换行正常，没有方框或模糊小字。
3. 检查鼠标悬停、按下和禁用按钮是否有明确反馈。
4. 重摇多张地图，确认水面、道路、地块和装饰没有明显穿模。
5. 完成五阶段施工，确认建筑比例、材质颜色和塔吊位置正常。
6. 缩放到最近与最远，检查文字、模型和地图是否仍可辨认。
7. 保存并读取，确认视觉重建不改变经营状态。
