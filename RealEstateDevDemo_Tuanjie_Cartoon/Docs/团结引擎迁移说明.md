# 团结引擎 1.10 迁移与卡通分支说明

更新日期：2026-11-03。

本目录 `RealEstateDevDemo_Tuanjie_Cartoon` 是从团结兼容分支继续制作的独立卡通美化工程。原 Unity 6 工程和旧团结兼容工程均保留，没有被本版覆盖。兼容目标仍贴近团结引擎的 Unity 2022 LTS 基线。

## 已做的兼容调整

### 1. 工程版本标记

`ProjectSettings/ProjectVersion.txt` 使用：

```text
m_EditorVersion: 2022.3.62t16
m_EditorVersionWithRevision: 2022.3.62t16 (ab17684acf1d)
m_TuanjieEditorVersion: 1.10.4
```

目的：避免团结引擎继续按 Unity 6 工程处理。版本标记只是迁移准备，不等于已经在团结 1.10 内实机运行。

### 2. 避免 Unity 6 对象查找 API

`DemoBootstrap` 和 `GameHUD` 使用 `FindObjectOfType<T>()`；本版静态检查未发现 `FindFirstObjectByType`、`FindAnyObjectByType` 或 `FindObjectsByType`。

### 3. 保守的渲染与输入路径

- Built-in Render Pipeline。
- uGUI + `StandaloneInputModule` + 旧版 Input Manager。
- `Resources.Load`、普通 `MonoBehaviour` 和 C# 运行时场景组装。
- 不依赖 TextMeshPro、新 Input System、URP / HDRP 或 Unity 6 专属 API。

### 4. 卡通分支追加修改

- 重写 `GameHUD`：1920×1080 原生参考画布、像素对齐、Smooth 动态中文双字体、抗锯齿圆角卡片、语义色按钮、完整锚定的滚动区和长文本溢出保护。
- 重写 `MapView`：平坦地表与实心地基、分层道路、立体地块角柱和招牌，以及路灯、花坛、长椅、别墅、树木和岩石。
- 新增 `ToonLit` 与 Resources 地形 Shader。
- 调整相机背景、方向光和环境光。
- 新增 20 个纯 Blender 程序化精细 FBX、透明城市图标与中文粗体；除地面外的建筑、机械、设施和植物均有真实立体几何。
- 编辑器资源检查同步覆盖全部新资源。

经营 Core、70% 预售门槛和已有存档结构没有因美术改造而改变。

### 5. 真实运行故障修复

用户在团结 1.10.4 中运行上一精细版后，实际截图出现红色地表、异常荧光绿色模型和多个按钮无字。本版据此进行修复：

- 查明按钮无字的直接代码原因：`Button` 给 `Label` 传入的是占位名 `"Text"`，且 `Label` 只请求字形、没有给 `Text.text` 赋值。现在所有 Label 都写入实际内容，按钮直接传真实标题。
- `PrepareDynamicGlyphs` 改为遍历全部 UI Text，按每个文本自己的内容、字号和样式请求字形。
- 删除 `Assets/Shaders/GridTerrain.shader` 与 Resources 中同名 Shader 的重复定义，只保留 Resources 版本。
- 地形改为显式 `COLOR` 语义 + 标准 Lambert；模型改用标准 Lambert，并移除色向外推和自定义光照曲线。
- 模型材质切换显式保存并恢复颜色、贴图；编辑器资源检查新增 `Shader.isSupported` 检查。

这些修改已经通过源码针对性检查和全量 C# 静态编译，但当前修复版本身仍需在真实团结中重新 Play 验收，不能沿用上一版的运行结果代替。

### 6. FBX 根旋转被覆盖导致的“纸板楼”修复

用户再次实机复测后，按钮标题和地表颜色恢复，但建筑基座竖起、楼体向画面深处躺倒。直接解析 `SM_HQ.fbx` 可见根节点 `SM_HQ` 含有 `Lcl Rotation = (-90, 0, 0)`，楼体与基座仍是正确的 Blender 局部坐标。

问题发生在运行时：旧 `ModelLibrary.Spawn` 直接返回 FBX 根实例，`MapView` 和 `ConstructionVisual` 再用 `Quaternion.Euler(0, yaw, 0)` 设置朝向，把根节点的 X = −90° 覆盖掉。因此这不是 Blender 楼体没有建模，而是导入轴向被游戏代码清除。

当前修复：

- `ModelLibrary.Spawn` 新建 `_Controller` 外层，返回外层而非 FBX 根实例；
- 外层使用 Identity 初始旋转，负责世界平移、统一缩放和游戏朝向；
- FBX 内层通过 `SetParent(controller, false)` 保留原始局部旋转与缩放；
- 所有建筑、树木、路灯和挖机动画继续旋转外层，不再覆盖内层轴向；
- 默认镜头改为 `yaw = 220`，避免修好后仍只展示没有门窗的背面。

本版未重新导出或改写 20 个 FBX，因为源模型与导出根旋转本身符合预期；修复点是 Unity 运行时层级。

## 推荐打开方式

### 方式 A：团结引擎 1.10 直接导入

1. 完整解压并保留其他版本作为备份。
2. 用团结 Hub / 团结引擎 1.10 打开 `RealEstateDevDemo_Tuanjie_Cartoon` 根目录。
3. 等待脚本、FBX、字体、图标和 Shader 首次导入。
4. 打开 `Assets/Scenes/Main.unity`。
5. 点击 **房地产 Demo → 检查 Demo 资源**。
6. 点击 Play，先将 Game 视图固定为 1920×1080、100% 显示比例检查 UI，再复测其他分辨率。
7. 完成从随机地图到结算的经营闭环，并测试保存、读取、暂停、加速和 Windows 打包。

### 方式 B：先用 Unity 2022.3 LTS 排查

如果团结首次导入失败，可用任何基于 Unity 2022.3 LTS 的编辑器打开同一分支，让引擎重建 Library。先确认 Console、资源检查和 Play，再回到团结引擎定位差异。

## 常见问题

### 打开时提示版本不匹配

确认打开的是 `RealEstateDevDemo_Tuanjie_Cartoon`，不是 `RealEstateDevDemo` 或旧兼容分支。如允许引擎迁移，先备份本目录，不要覆盖原版。

### FBX 不显示或变成方块

查看 Console 警告中的资源名，确认 20 个 FBX 已完成导入。必要时右键 `Assets/Resources/Models` → Reimport，再执行资源检查。占位方块表示加载失败，不是正常卡通效果。

### 按钮只有背景、标题为空

这不是分辨率问题。确认 `GameHUD.Label` 中存在 `text.text = value;`，并且 `Button` 调用的是 `Label(go.transform, label, ...)` 而不是传入占位名 `"Text"`。修复版已包含这两处修改；若从旧工程手动合并，不能只复制 Shader 而漏掉 GameHUD。

### 地表变红或模型出现异常荧光色

先执行 **房地产 Demo → 检查 Demo 资源**，确认两个 Lambert Shader 均受当前图形后端支持，并检查 Console 的 Shader 编译信息。确认工程内没有第二份 `RealEstate/GridTerrain`，也不要把旧版 `LightingToonRamp` / `LightingTerrainRamp` 合并回来。修复版的模型颜色来自 FBX 材质，地形颜色来自 Mesh 顶点色。

### UI 模糊或仍像旧版

先固定 Game 视图到 1920×1080，以 100% 比例检查；确认加载的是本修复版分支。若文字不完整，检查 GameHUD 中左右 ScrollRect 是否仍完整锚定，不要通过继续缩小字号掩盖布局问题。若 Library 缓存异常，关闭引擎后仅删除本分支的 Library 再导入。按钮完全无字或场景异常纯色不属于正常缩放现象，应按上面两项检查。

### UI 不能点击

检查是否有 `EventSystem`。正常时 `GameHUD.Build()` 会自动创建；若意外删除，手动添加 `EventSystem` 与 `StandaloneInputModule`。

### 输入系统异常

Project Settings → Player → Active Input Handling 选择 **Input Manager (Old)** 或 **Both**。
